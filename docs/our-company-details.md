# Our company details

Create/Edit Project uses an optional `OurCompanyId` relationship to SQL `CompanyMasters`. The section follows Project Information and precedes Client Details. The searchable selector displays `DisplayName` and filters both company and display names from one loaded list. All contact fields and the logo come from the selected row and are read-only. Editing a project never updates company master data.

The import source is `IHM_Company.xlsx`, Sheet1 rows 3–13, columns A–H. The eleven nonempty rows remain separate options, including repeated company names. `Assets/Companies.json` preserves their source values; stable IDs derive from the unique display label, and SQL enforces a unique DisplayName. Migration seeding runs once through EF migration history, so repeating database update does not insert duplicates. Runtime requests read SQL, not Excel. The source workbook is unchanged.

The workbook references `aries_mar_engg.png`. The existing original logo was copied from `AURAS_API_LATEST/wwwroot/company-logos` into this API's `Assets/CompanyLogos` and embedded. `GET /api/companies` supports optional `search`; authenticated `GET /api/companies/{id}/logo` streams an available logo without exposing physical paths. Missing contact fields show `-`; missing logos show `No logo available`.

Project responses include `ourCompanyId` and `ourCompany`. Reports resolve the same relationship and include the selected name, address, telephone, fax, website, email and logo. The top-right ARIES artwork is fixed; only the lower company block has dynamic branding and contacts; full contacts appear in the cover company block. Projects without a company continue to create, edit and generate reports with clean placeholders. Existing project metadata uppercase rules do not alter master emails, websites or other imported values.

Migration `20261007131230_OurCompanyMaster` creates the company master, imports eleven records and adds nullable `Projects.OurCompanyId`. It was applied to the local database. For another database, apply normal EF migrations with `Update-Database` in Package Manager Console or `dotnet ef database update` from the API repository. The equivalent incremental SQL is in `our-company-master-migration.sql`; apply it only after `ProjectReportMetadataAndClientDetails` and do not apply both SQL and EF updates independently.

Verification: frontend company selection/search/switch/read-only tests, existing workflow regression tests, authenticated HTTP create/edit/reload/master/validation tests, backend report generation and local SQL row comparisons. `--report-sql` verifies persisted imported values and generates a read-only sample from an existing project; it does not assign a company to that project. Web build and backend builds pass. Native device behavior still requires a device check.
