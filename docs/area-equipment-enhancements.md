# Area equipment form and project sequencing

The shared full-page Area Equipment Add/Edit form uses Item Tag, Equipment ID / Ex-Tag, Location / Area and Zone / Division. Protection Type uses ExProtectionType, which supplies the HAER Protection column. ProtectionDetails has a separate legacy meaning: its field is hidden, but existing values are still loaded and returned unchanged on edit. Manufacturer SerialNumber is unchanged.

All new AreaEquipment records, including RFID/manual bulk creates, receive their final SequenceNo through SurveyDbContext.SaveChangesAsync. SQL Server uses an exclusive project-specific transaction application lock. The allocator reads the maximum existing sequence and durable EquipmentSequence audit markers, assigns numbers in creation order, and saves the equipment plus the new high-water marker atomically. Deleting equipment also records the high-water value, preventing reuse even if deletion occurs before the first new addition. Historical rows are not renumbered; existing duplicate historical numbers remain untouched. Numbers deleted before this feature existed cannot be reconstructed if no historical record remains. The next number is assigned at save time rather than displaying a potentially stale client-side reservation.

The shared form displays the existing sequence on edit and an automatic-assignment notice on add. HAER exports now display the stored sequence rather than a row index, retaining the approved report columns.

Selected images have thumbnails and a zoomable View Photo preview. Saved photos load in the edit form and can be viewed, supplemented, removed or replaced. Upload failures leave the form and selected files available for retry. Replacement uploads first and removes the previous association only after the upload succeeds. If subsequent removal fails, both images may remain and the error is displayed. Removal checks existing project access and equipment/area association; inspection-session photographs are excluded. Original stored equipment evidence is retained with an audit reference when its live form association is removed.

No schema migration is required: sequence high-water values use the existing AuditLogs table. Deploy backend and frontend together. No live database was changed. SQL Server concurrent-writer locking was reviewed; automated sequence tests use an isolated InMemory database and are not a SQL Server load test. Existing project HTTP and workflow regression checks pass, as do 202 frontend tests and TypeScript. The production web build passes with its existing performance warnings.
