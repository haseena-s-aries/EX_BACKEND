## Data-loss and concurrency risks

Photo upload is implemented against API filesystem storage with authenticated reads, but the live file-picker flow was not approved for testing; no offline durable queue, resumable upload or replication exists. The new activity path preserves accepted activity/checkpoint history, while legacy SurveySession edits during QC InReview retain their existing risk. The synthetic LocalDB database passed backup/restore; production recovery remains unverified.

## Security notes

Treat prior tracked values as compromised even though current JSON is cleaned; rotate and revoke them, then decide history remediation with the repository owner. OTP attempt limits and endpoint/IP throttling are now implemented. Continue reviewing authorization on all resource routes for tenant ownership; add security headers, durable audit retention, mobile secure storage and penetration testing. Do not infer that JWT validity alone proves resource-level authorization.
